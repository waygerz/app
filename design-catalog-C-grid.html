Data Grid

Treat cards and the table as one grid. Every list is built on the same four-column template — lead · primary · meta · metric — so a standings list, the wallet ledger and the schedule "table" literally line up on the same columns and the same dense row height. Numbers are monospaced and right-aligned; an optional mono column header labels the metric. Best for scanning and power users; unifies the last <table> by making everything table-grade.

What standardizes. There is exactly one layout — a four-column grid — and the ledger, standings, open bets and schedule are all instances of it, so their columns align and scanning down any list feels the same. The lone <table> stops being special: it's the same grid with a wider lead column. State is a rigid 4px tick so it never disrupts alignment. Densest and most scannable; the trade-off is it reads more "app/spreadsheet" than "social" — softer, hero-style cards (invite previews, profile) would sit outside this grid as deliberate exceptions.
